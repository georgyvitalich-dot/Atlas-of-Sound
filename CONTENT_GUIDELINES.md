# Atlas of Sound — Artist Data Standard

Единственный источник правил для музыкального контента. Всё, что добавляется в
`src/data/countries/*/content/`, должно ему соответствовать. Автоматическая часть
правил проверяется валидатором (`npm run validate:data`); остальное — ответственность
автора записи.

> Принцип: **меньше, но правда.** Лучше пустая эпоха, чем притянутый артист.
> Лучше без года рождения, чем с выдуманным.

---

## 1. Кто попадает в атлас

Артист (человек или коллектив) релевантен, если выполнено **хотя бы одно**:

- изменил развитие жанра или сцены (новый звук, стиль, технология);
- имел крупный национальный/международный успех (хиты №1, платиновые альбомы, главные премии);
- определяет музыкальную идентичность штата или города (без него история места неполна);
- признан ключевой фигурой сцены авторитетными источниками, даже без массового успеха.

Не добавляем: артистов «для заполнения эпохи», одноразовые вирусные хиты без влияния,
участников, которые уже представлены через свою группу (если сольная карьера не стала
самостоятельной историей).

## 2. Принадлежность к штату (`regionId`)

У артиста **одна** запись и **один** штат — место, где сформировалась его музыкальная
идентичность и где он был впервые замечен. Порядок решения:

1. **Место становления** — где артист вырос как музыкант, записал ранние/определяющие работы,
   был частью сцены (Aretha Franklin → Мичиган, хотя родилась в Мемфисе).
2. **Культурная идентификация** — если артист прочно ассоциируется со штатом в культуре
   и собственном творчестве (Ray Charles и «Georgia on My Mind»; Tina Turner и «Nutbush City Limits»).
3. **Место рождения** — только если 1–2 не дают ответа.

Место рождения всегда сохраняется в `birthplace`, даже если штат другой.

## 3. Город (`cityId`, `district`, `birthplace`)

Три разных понятия — не смешивать:

| Поле | Что это | Пример (Elvis Presley) |
|---|---|---|
| `birthplace` | где родился человек (строка, «Город, Штат») | `Tupelo, Mississippi` |
| `cityId` | город, с которым артист связан **музыкально** (сцена, лейбл, студия, клубы) | `us-tn-memphis` |
| `district` | *необязательно*: район/улица/сцена **внутри** этого города | `Beale Street` |

**Редакционное правило (Stage 3B).** `cityId` = главный город, с которым артист/группа прежде всего
связаны в контексте музыкальной сцены Atlas of Sound. Это редакционная модель атласа, а не
претензия на единственно верную историю.

Правила:

- Для групп приоритет:
  1. город образования, если он — очевидная часть музыкальной идентичности
     (O'Jays → Canton, Nirvana → Aberdeen, Earth, Wind & Fire → Chicago);
  2. иначе — главный город ранней/ключевой сцены (Metallica → San Francisco,
     Allman Brothers → Macon, Portugal. The Man → Portland); место образования — в описании;
  3. другие города — через `places` (§13), не второй записью.
- Если описание называет другой город, чем `cityId`, оно должно объяснять связь
  (Fugees: «Formed in South Orange, just outside Newark»).
- Пригород без собственной музыкальной истории → основной город агломерации, **без** `district`
  (Migos из Лоуренсвилла → `us-ga-atlanta`; пригород можно упомянуть в описании).
- Пригород/город с собственной сценой → отдельная запись в `geo/cities.ts`
  (El Cerrito для CCR, Berkeley для Green Day, Ann Arbor для The Stooges).
- `district` — только настоящий район, улица или сцена внутри города (Harlem, Beale Street,
  Third Ward, Sunset Strip). Нельзя: отдельные города («Hawthorne, Los Angeles» — неверно).
- Новый город: `id = <regionId>-<slug>`, `coords = [lon, lat]` (сначала долгота!). Валидатор
  проверяет, что точка лежит внутри штата.

## 4. Даты (`born`, `formed`)

- Человек: `kind: 'person'`, `born` = `YYYY-MM-DD` или `YYYY`, только подтверждённые.
- Группа: `kind: 'group'`, `formed` = год образования (под этим или ранним названием,
  если состав и идея преемственны).
- **Спорный год рождения** (источники расходятся) → поле `born` не заполняем; причину
  можно указать в описании. Валидатор помечает это как `INFO`, а не ошибку.
- Дуэты, семейные коллективы, «X & the Y» — это `group`.

## 5. Эпохи (`eras`)

- **Редакционное правило (Stage 3B).** `eras` = десятилетия значимой музыкальной активности
  или влияния артиста в контексте атласа — не только год дебюта и не только пик карьеры.
  Если артист был значим в нескольких десятилетиях, указываем их все
  (Jay-Z: 1990-е и 2000-е; Isaac Hayes: Stax-1960-е и 1970-е).
  Не включаем десятилетия, где артист лишь продолжал гастролировать.
- Первая эпоха не может начинаться до ~12 лет артиста (валидатор проверяет).
- Для каждой эпохи из `eras` карточка показывает трек: `eraTracks[эпоха] ?? featuredTrack`.
  Если трек не из этой эпохи — валидатор выдаёт `INFO`; добавьте проверенный `eraTracks`
  либо пересмотрите, действительно ли эпоха значима.

## 6. Жанры (`genres`)

- 1–3 определяющих жанра, первый — главный (он задаёт цвет монограммы).
- Только id из `src/data/genres.ts`. Нового жанра не хватает → добавить его туда
  (id, три локали, цвет), а не подменять ближайшим.
- Жанр должен описывать музыку артиста, а не сцену вокруг (house → `electronic`, funk → `soul`/`rnb`).

## 7. Значимость (`significance`, 1–5)

Определяет порядок: превью показывает 3 самых значимых артиста эпохи.

| | Критерий | Примеры |
|---|---|---|
| **5** | Канон: изменил ход жанра или американской музыки в целом | Elvis, Aretha Franklin, Louis Armstrong, Muddy Waters, Beyoncé |
| **4** | Крупное национальное влияние: определяющие хиты/альбомы, влияние внутри жанра | Eagles, Metallica, Gladys Knight & the Pips |
| **3** | Заметный: важные хиты или сильное влияние на сцену, важен для истории штата | The Meters, Big K.R.I.T. |
| **2** | Сцена/регион: культовое или локальное влияние | — |
| **1** | Для полноты истории места | — |

Ориентир: «5» — не больше ~40% артистов штата (валидатор предупреждает при > 45%).

## 8. Треки (`featuredTrack`, `eraTracks`)

- `featuredTrack` — самая узнаваемая **и** характерная запись артиста; год = год первого
  релиза (сингл или альбом — что раньше).
- `eraTracks` — для каждой дополнительной эпохи, если есть проверенный трек этого десятилетия.
  Год должен лежать внутри эпохи (валидатор проверяет).
- Название — как на официальном релизе. Трек должен исполняться самим артистом
  (для продюсеров — их собственный релиз).
- Ссылки Spotify/YouTube не придумываем: без `links` приложение строит поиск по
  «артист + трек». Точную ссылку (`https://open.spotify.com/...`, `https://www.youtube.com/...`)
  добавлять только проверенную.

## 9. Описания (`description`)

- Одно предложение, ≤ 220 символов, во **всех трёх** локалях (en, pl, ru).
- Отвечает на вопрос «почему этот артист важен для этого места и эпохи».
- Только проверяемые факты; оценки — умеренные и общепринятые («один из», а не «лучший»).
- Не повторять то, что уже видно в карточке (год, город, жанр).
- Имена собственные, названия песен и альбомов не переводятся; кавычки: “en”, „pl”, «ru».
- Нейтральный тон; для людей, чьи местоимения неизвестны, — формулировки без местоимений.

## 10. Изображения

Только с понятной лицензией (Wikimedia Commons и т.п.): `image = { src, credit, license }`.
Без лицензии — не добавлять (UI покажет монограмму).

## 11. Дубли и артисты нескольких штатов

- Один артист = одна запись (валидатор ловит дубли id и имён, без учёта «The» и регистра).
- Связь с другими штатами — через `birthplace` и описание, **не** через вторую запись.
- Группа и её лидер — разные записи, только если сольная карьера самостоятельно значима.

## 12. Недостаточно достоверной информации

- Факт не подтверждается хотя бы одним надёжным источником (Википедия с источниками,
  AllMusic, Grammy/Billboard, официальные сайты, Library of Congress) → **не добавлять**.
- Можно добавить артиста без спорного поля (`born`), но не с угаданным значением.
- Сомнительные случаи записывать в отчёт пулл-реквеста/сессии, а не в данные.

## 13. Факты, связи с местами, источники (Data Model 1.1)

Все поля этого раздела **необязательные**. Заполняются только подтверждёнными данными;
неизвестное оставляем пустым. Валидатор проверяет их, только если они заполнены.

- **Факты vs редакция.** Факты (`ArtistFacts`): `born`, `formed`, `disbanded`, `activeFrom`/`activeTo`,
  `birthplace`, `cityId`, `district`, `regionId`, `genres`, `places`, год трека.
  Редакция (`ArtistEditorial`): `eras`, `significance`, выбор `featuredTrack`/`eraTracks`, `description`.
  Эпохи — навигация атласа, а не даты: реальные даты их не заменяют.
- **`activeFrom` / `activeTo`** — первый и последний год музыкальной активности.
  Нет `activeTo` = активен или неизвестно. Если span задан, эпохи должны с ним пересекаться (предупреждение).
- **`disbanded`** — только для групп: год (первого) распада.
- **`places`** — дополнительные документированные связи с местами:
  `bornIn`, `formedIn`, `basedIn`, `activeIn`, `associatedWith`. Каждая связь — либо `cityId`
  (город атласа), либо `place` (текст, для мест вне атласа), плюс опционально `from`/`to`/`sources`.
  Основной `cityId` здесь **не повторяем**; `birthplace` остаётся подписью для людей.
- **`sources`** — `{ url?, title?, type?, supports? }`, нужен `url` (https) или `title`.
  `supports` перечисляет, какие факты подтверждает источник (`['born', 'activeFrom']`).
  Источники можно указать у артиста и у отдельной связи в `places`.

## 14. Сцены (`content/scenes.ts`)

Сцена — редакционная группировка артистов вокруг мест и периода (Motown, Chicago blues).

- **Состав задаётся явно** (`artistIds`), а не вычисляется из «город + жанр + эпоха»:
  соул Детройта 1960-х ≠ Motown. Только артисты этого датасета; других можно назвать в описании.
- `cityIds` — один или несколько городов атласа; регион сцены следует из городов.
- `eras` — навигационные эпохи сцены; `from`/`to` — фактические годы, только подтверждённые.
- `related` — направленные связи `influenced` / `evolvedInto` / `contemporaryOf` на другие сцены.
- `description` ≤ 220 символов на EN/PL/RU. Имена собственные в `name` сохраняем, описательные переводим.
- Валидатор: ошибки — дубль id, неизвестные город/артист/жанр/эпоха, битая или
  ссылающаяся на себя связь, пустой перевод, сцена без городов или артистов;
  предупреждения — меньше 2 артистов, артист без общей эпохи или жанра со сценой,
  город артиста не входит в города сцены (допустимо, но должно быть осознанно).

## Обязательные поля

| Поле | Обязательно | Проверка |
|---|---|---|
| `id` | да | kebab-case, уникальный |
| `name` | да | уникальный |
| `kind` | да | `person` / `group` |
| `born` / `formed` | да* | формат, реальная дата (*`born` можно опустить при споре) |
| `birthplace` | для людей | предупреждение, если нет |
| `regionId`, `cityId` | да | существуют, город лежит в этом штате |
| `district` | нет | не пустая строка |
| `genres` | да | 1–3, из реестра |
| `eras` | да | из реестра, без дублей |
| `significance` | да | целое 1–5 |
| `featuredTrack` | да | название, год 1900…текущий, не раньше ~10 лет артиста / образования группы |
| `eraTracks` | нет | ключи ⊂ `eras`, год внутри эпохи |
| `description` | да | en/pl/ru, ≤ 220 символов |
| `links`, `image` | нет | https Spotify/YouTube; у image — credit и license |

## Процесс добавления штата

1. `geo/cities.ts` — города штата (`<regionId>-<slug>`, `[lon, lat]`).
2. `content/regions.ts` — `tagline` и `summary` (en/pl/ru), editorial, не официальный слоган.
3. `content/artists/<код>.ts` — артисты по этому стандарту; подключить файл в `content/artists/index.ts`.
4. `npm run content:report` — таблица полноты по всем 50 штатам + `reports/content-status-us.md`.
5. `npm run validate:data` — ноль ошибок; предупреждения и заметки просмотреть.
6. `npm run build` (валидация встроена в сборку — с ошибками данных сборка не пройдёт).

## Шаблон записи

```ts
{
  id: 'artist-name', name: 'Artist Name', kind: 'person', born: '1950-01-31',
  birthplace: 'City, State', cityId: 'us-xx-city', district: 'Neighborhood', // district — опционально
  regionId: 'us-xx', genres: ['soul', 'rnb'], eras: ['1960s', '1970s'], significance: 3,
  featuredTrack: tr('Song Title', 1971),
  eraTracks: { '1960s': tr('Earlier Song', 1966) },
  description: {
    en: 'Why this artist matters for this place and time — one sentence.',
    pl: '…',
    ru: '…',
  },
},
```
